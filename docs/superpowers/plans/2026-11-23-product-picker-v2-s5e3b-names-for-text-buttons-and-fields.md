S5e-3a pinned 13 buttons whose only words live in a child `Text` and that set neither a name nor their own `text`. ## 2. Decisions (each has a default; veto in the PR)

**S5e3b-D1. One slice or two?** S5e-3a-D1 named two jobs for S5e-3b: the text-child buttons and the font-scale and two-theme audit. For one slice: the roadmap lists them together. Against: the audit is a read of about 60 QML files for hard-coded pixel sizes and colours whose findings need design calls (what to do at 2.0x font), and a PR that mixes 14 one-line accessibility edits with that audit is slow to review and slow to resume on another account. **Taken: split. S5e-3b (this) = names. S5e-3c = font and theme audit, then S5e-4.**

**S5e3b-D2. How is a text-child button named?** (a) `Accessible.name: <id>.text` pointing at the drawn `Text`, and that `Text` gets `Accessible.ignored: true`; (b) own `text` plus a `contentItem` that draws `text` (the S5e-3a "Manage channels" recipe, Skill 186 rule 5); (c) a copy of the label in `Accessible.name: qsTr("...")` (two strings that can drift). For (a): one `qsTr` stays where it is, name and picture cannot drift, zero layout change, and it works when the drawn words are a ternary (Sales "See all" / "Show less"). For (b): needed when the drawn words carry a glyph the screen reader must not say (Dashboard "See all  ›"). Against (c): drift, and a translator sees the word twice. **Taken: (a) by default, (b) for the one link with a chevron.** Every button that takes (a) or (b) hides the child `Text` from the screen reader, so a swipe makes one stop, not two.

**S5e3b-D3. Names that say WHICH row.** The Default and Remove buttons of Manage categories and Manage order channels sit on rows that repeat the same visible word "Default" and "Remove" up to dozens of times. A user who lists controls (TalkBack's controls menu) hears the same word N times. They speak "Set Tea as default" and "Remove Tea", the same way S5c named the cart stepper "Quantity of X". The name still contains the visible word (WCAG 2.5.3, label in name). Cost: one `%1` in four `qsTr` literals; the item name is data and is read verbatim.

**S5e3b-D4. Member buttons say which member (KI 124).** `Suspend %1`, `Activate %1`, `Remove %1` with `card.memberLabel` = display name, else email, else the word "member". Remove is destructive; a confirm sheet follows, so this is a clarity fix, not a safety gate. S5e-3a's rule "no `%1` in an icon name" (`S5E3-22`) is relaxed for exactly these three on purpose (the test now lists them).

**S5e3b-D5. The four order fields (KI 120).** `Price of %1`, and for the discount `Discount of %1, percent` or `Discount of %1, flat amount` (the unit toggle sits beside the field, so the name says which unit the number is in; a user who changes the toggle hears the new unit on the next focus). `%1` is the product name. Alternative: one word "Discount" and let the toggle speak: the number and the unit are then two stops that can disagree in the user's head. **Taken: the unit in the name.**

**S5e3b-D6. Settings rows (Profile).** `SettingsRow` is a component whose root is a button; the name is `label` plus `, trailingText` when there is one ("Language, English"), one stop; the two child `Text`s are ignored. The `", "` join is a concatenation that a translator cannot reorder; it joins two DATA strings (a row label and a value), not words of a sentence, and `S5E3B-22` exempts exactly this one expression. The UID button keeps its `ID: abcdef…wxyz` text readable (the value is the point) and gets the name "Copy user ID" (what a tap does).

**S5e3b-D7. Tab bar.** Each tab's name is its label. `Main.qml` passed `"Home"`, `"Orders"`, `"Stock"` as bare strings (only "Analysis" was `qsTr`): wrapped, so the one place the tab words are spoken is translatable. A selected-state word (TalkBack says "selected" for a checkable button; the tab is not `checkable`) is NOT added: the tab's active colour and bold are visual only. Written down (KNOWN-ISSUES 130).

**S5e3b-D8. Not named here, on purpose.** (a) `InventoryPage` `ProductCard`: a card button that holds Restock, Edit, Delete buttons; naming the card risks a double read, same class as `ListCard` (KI 123), decide on a device (checks 176 to 179). (b) `helper/SegmentedNav.qml`: no user anywhere (dead code, like `OrderRow`, KI 121). (c) `AuthTextField`, `AuthPasswordField`, and the workspace field of Profile settings (KI 120 left, 3 fields): login and settings screens, not the picker arc; a visible label sits above them. Each is pinned by a ratchet so it cannot grow unseen.

**S5e3b-D9. A guard was too loose (found by this slice).** `completionsSyncingWiring.test.js` checked that the "Saved. Syncing" caption has a name by searching for `Accessible.name: qsTr(` anywhere from that caption to the END of `OrderDetailDialog.qml`. Adding two names lower in the same file made its own mutant ("accessible name removed") survive. The check is now scoped to the caption's own block. Lesson in Skill 187 rule 6.

## 4. Test strategy
Node only (no Qt in the sandbox, CI is the oracle). A table of the 11 buttons runs each real name expression in a sandbox with a `qsTr` that has the real `.arg`; the drawn `Text` of every "ref" button is found by id and must be ignored; the "own" link keeps its chevron out of the name; every name that can carry a row word contains the visible word; both states of the Sales toggle and the Settings row differ; handlers and sizes are pinned. Ratchets: text-child unnamed buttons (2 left, by file), named buttons that still read a child (2, by file), unnamed text fields (3, by file), the dead `SegmentedNav`, the `ProductCard` reason. Monkey: 19 hostile item names (`%1`, `$&`, quotes, emoji, Devanagari, 300 characters, newline, `text: x`) plus 300 seeded random ones must come through every per-row name verbatim and never throw; 300 seeded generated blocks check the field scanner against its generator. Hand mutants: 33 (see section 6).
